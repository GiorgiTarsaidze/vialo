## The three findings, and why each is not a credential

1. docs/kiro-evidence/regenerate-journal-verification.sh:87   rule: jwt
   An unsigned "alg=none" JWT used as an attack probe against the Journal API.
   Header  : {"alg":"none","typ":"JWT"}
   Payload : {"sub":"attacker","aud":"6lue0pok3ga0qsnmk8knmcq82l","exp":9999999999}
   Signature: empty.
   The audience is the Cognito app client id, which is public client configuration
   present in the browser bundle by design. The token carries no signature, so the
   backend rejects it; the battery asserts exactly that, and records a 401.
   Its purpose is to prove the API refuses a forged token, so removing it would
   remove the evidence.

2. frontend/tests/journal.test.tsx:337   rule: generic-api-key
3. frontend/tests/journal.test.tsx:364   rule: generic-api-key
   Test fixtures for the signed-in author check in JournalPostView.
   Values  : eyJhbGciOiJSUzI1NiJ9.eyJzdWIiOiJ1c2VyLTEifQ.sig
             eyJhbGciOiJSUzI1NiJ9.eyJzdWIiOiJ1c2VyLTk5In0.sig
   Decoded : {"alg":"RS256"} / {"sub":"user-1"} and {"sub":"user-99"}
   The signature segment is the literal three-character string "sig". These are
   shaped like a JWT so the component's parser has something to parse, and they
   authenticate nothing anywhere.

No finding is a live credential, and none grants access to anything.
